# memory/types/perceptual.py

## 一、这个文件是干什么的

这个文件是四层记忆系统里「感知记忆（Perceptual Memory）」这一层的类型声明文件，整个文件只有 12 行，职责非常单一：定义一个可被记忆系统统一调度与识别的记忆类型。文件顶部用一行文档字符串 `"""Perceptual memory for multimodal payloads."""` 说明它的用途是承载多模态载荷（例如图像、音频、视频、截图、语音转写等非纯文本内容）的感知类记忆。它通过 `from __future__ import annotations` 启用延迟注解求值，保证类型注解在运行期不会被立即解析成对象，从而避免循环导入或前向引用问题；随后从上一级包 `..base`（即 `memory/base.py`）导入 `BaseMemory` 与 `MemoryType` 两个基础设施符号。文件的主体是模块级类 `PerceptualMemory`，它继承 `BaseMemory`，并唯一地覆盖了类属性 `memory_type = MemoryType.PERCEPTUAL`，以此把自己登记为「感知记忆」这一枚举类型。文件末尾用 `__all__ = ["PerceptualMemory"]` 显式声明包的公开导出面，使得 `from memory.types.perceptual import *` 只会导出这一个类名，同时也向静态检查工具和 IDE 表明这是该模块对外的正式接口。在项目运行时，这个类本身不含任何业务逻辑，它承担的是「类型标签 + 继承骨架」的角色：记忆管理器、存储后端、检索路由等上层组件通过识别 `memory_type` 的值，把多模态感知数据分发到与文本记忆、情景记忆、语义记忆不同的存储与检索通道中去。因此可以把它理解为四层记忆体系中的一层「占位与标识」实现，真正的读写、序列化、相似度计算等能力都来自父类 `BaseMemory` 与外部调用方，而不是本文件。

### `PerceptualMemory.memory_type = MemoryType.PERCEPTUAL` （第 9 行）
- **作用**：这是本文件里唯一的类属性赋值，也是整个文件最核心的一行。它把 `PerceptualMemory` 这一类记忆的类型标签固定为 `MemoryType` 枚举中的 `PERCEPTUAL` 成员，从而让上层代码可以通过读取实例或类的 `memory_type` 属性，判断当前记忆是否属于感知记忆。之所以要在子类里重新赋值覆盖，是因为父类 `BaseMemory` 必然也定义了同名的 `memory_type`（否则这一行就只是新增属性而非覆盖），四层记忆的每一个子类都通过这种方式各自声明自己的归属，形成一个「同名属性、不同取值」的多态标签体系。它会在记忆实例被创建、被序列化、被反序列化、被加入记忆库或被按类型检索时被反复读取。由于它是类属性而不是实例属性，所有 `PerceptualMemory` 实例共享同一个值，读取时不需要实例化，直接 `PerceptualMemory.memory_type` 即可取到，这在做类型路由和注册表构建时非常方便且开销极低。
