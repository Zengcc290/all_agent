# memory/types/episodic.py

## 一、这个文件是干什么的

这个文件是整个四层记忆系统中「情景记忆（Episodic Memory）」这一层的具体实现文件，它把抽象的基类能力落地成一种专门用来存放「带时间戳的事件序列」的记忆类型。

从代码上看，它非常短小精悍，全文件只有 19 行，主要包含三样东西：一是从上级包 `..base` 中导入 `BaseMemory`、`MemoryItem`、`MemoryType` 这三个基础构件；二是定义了一个模块级类 `EpisodicMemory`，它继承自 `BaseMemory`，并通过类属性把自身登记为 `MemoryType.EPISODIC` 这一记忆类型；三是在这个类里提供了唯一的公开方法 `record`，用来把一条「发生了什么事」的事件文本连同时间戳、元数据和重要度写入记忆库。

在项目运行中的作用是：当 Agent 运行时需要记住「某时某刻发生了什么」这类按时间排列的经历（例如某次对话轮次、某个工具调用事件、某个观察结果），就会拿到 `EpisodicMemory` 的实例，调用它的 `record(...)` 方法，由该方法转交给基类 `BaseMemory.add(...)` 完成真正的存储、向量化或落库工作。

它的设计思路是典型的「薄封装」：本文件不重复实现任何存储逻辑，只负责把情景记忆特有的语义（事件文本 + 时间戳）翻译成基类通用的 `add` 调用签名，从而保证情景记忆与其他记忆类型（语义记忆、程序记忆等）共享同一套底层机制，同时各自对外暴露贴合自身语义的接口。

也正因如此，这个文件是整个记忆类型目录中最容易被上层记忆管理器统一调度的一环：只要拿到了 `MemoryType.EPISODIC`，上层就能定位到 `EpisodicMemory` 这个实现类，并调用它统一的 `record` 入口写入事件。

## 二、函数与类逐条详解

### `class EpisodicMemory(BaseMemory)` （第 12 行）

- **作用**：这是情景记忆的实现类，代表四层记忆体系中专门负责「按时间顺序记录事件经历」的那一层。它继承自 `BaseMemory`，因此自动获得了基类提供的存储、检索、删除、持久化等全部通用能力，而自身只需要声明「我属于哪种记忆类型」以及「如何记录一条事件」这两件情景记忆特有的事。之所以需要它，是因为不同类型的记忆在语义上差别很大：情景记忆关心「什么时候发生了什么事」，因此需要一个带时间戳参数、语义上叫「记录事件」的入口，而不是让调用方直接面对通用的 `add`。当 Agent 需要保存一段可回溯的经历（例如一次工具调用、一次用户交互、一次环境观测）时，就会实例化或复用它，通过 `record` 写入。同时，类属性 `memory_type = MemoryType.EPISODIC` 让上层记忆管理器能够通过类型枚举把该实例与其他记忆实现区分开，从而做分类存储、分类检索和分层召回。
- **参数**：类本身没有在文件中定义 `__init__`，因此没有本文件层面可见的构造参数；实例化时实际使用的构造签名完全由父类 `BaseMemory` 决定（本文件不做任何覆盖）。唯一的类级属性是 `memory_type`，它被赋值为 `MemoryType.EPISODIC`，这是一个枚举成员，作为该类的身份标识，不接收外部传参，也不应被实例修改。
- **返回**：类不是一个函数，没有返回值；对它求值得到的是一个类对象，调用 `EpisodicMemory(...)` 得到的是该类的实例（同时也是 `BaseMemory` 的实例）。
- **内部流程**：类定义体内只做了一件事——执行 `memory_type = MemoryType.EPISODIC` 这条类属性赋值语句，把这个枚举值挂到类命名空间上；随后定义方法 `record`。因为继承了 `BaseMemory`，Python 在创建这个类时会建立 MRO（方法解析顺序），使 `EpisodicMemory` 的实例在访问 `add`、检索等方法时自动回溯到 `BaseMemory` 上查找。文件末尾的 `__all__ = ["EpisodicMemory"]` 把该类登记为模块对外导出的唯一符号，影响的是 `from ... import *` 时的行为，而不是类的运行流程。
- **异常/边界**：本文件中的类定义本身不会抛出异常；`memory_type` 依赖导入的 `MemoryType.EPISODIC` 存在，若该枚举成员缺失，会在模块导入阶段就抛 `AttributeError`。除此之外没有对空值、非法值或超时的任何特殊处理，构造期的异常与边界完全取决于父类 `BaseMemory`。
- **同文件关系**：它定义并包含本文件唯一的实例方法 `record`；`record` 反过来调用父类 `BaseMemory.add`（属于外部/父类，不在本文件内）。本文件内没有其他类或函数调用它，但它通过模块级 `__all__` 被声明为对外导出项。

### `record(self, event: str, *, timestamp: datetime | str | None = None, metadata: Mapping[str, Any] | None = None, importance: float = 0.5) -> MemoryItem` （第 15 行）

- **作用**：这是情景记忆对外暴露的唯一写入入口，语义上表示「记录一条发生过的、带时间戳的事件」。它存在的意义是把情景记忆特有的调用语义（主语是「事件 event」，天然带有「何时发生 timestamp」）适配成基类通用的 `add(...)` 签名，这样调用方在写情景记忆时不需要了解底层的 `add` 参数顺序，也能获得一个语义更清晰的 API。它通常在 Agent 运行过程中被触发：例如一次工具调用完成、一轮对话结束、一次环境观测产生时，上层会调用 `record` 把这段经历持久化。方法本身不做任何存储、去重、时间解析或向量化，是一个纯粹的转发/适配层，因此非常轻量，也保证了所有情景记忆写入路径最终都汇聚到基类同一套逻辑上，便于统一维护。
- **参数**：
  - `self`：`EpisodicMemory` 实例本身，由 Python 在方法调用时自动传入，用于在转发时绑定基类方法（通过 `self.add(...)` 调用），不需要调用方显式提供。
  - `event: str`：位置参数，必填，表示要记录的事件内容文本（例如一句对发生了什么事的自然语言描述）。类型标注为 `str`，代码中没有做运行时类型校验，因此如果传入非字符串对象，行为取决于基类 `add` 如何处理。
  - `timestamp: datetime | str | None = None`：关键字专用参数（因为前面有 `*` 分隔符），默认值为 `None`，表示该事件发生的时间。类型上允许三种形态：`datetime` 对象、字符串形式的时间表达、或者 `None`。当传入 `None` 时，语义上表示「未指定时间」，具体是补当前时间还是留空由基类 `add` 决定；传字符串时如何解析（例如是否为 ISO 8601）同样由基类负责，本文件不做解析或校验。
  - `metadata: Mapping[str, Any] | None = None`：关键字专用参数，默认 `None`，用于携带该事件的附加结构化信息（例如来源、参与者、标签、关联的会话 id 等）。类型标注为 `Mapping[str, Any]`，说明期望的是一个只读的键值映射（`dict` 是其常见实现）；`None` 表示没有额外元数据。本方法只做透传，不复制、不修改该映射。
  - `importance: float = 0.5`：关键字专用参数，默认 `0.5`，表示该事件的重要程度，用于后续召回排序或衰减策略。代码中没有对其取值范围做任何限制或断言，因此理论上传入任意浮点值（包括负数、超过 1 的值）都会被原样转发给基类，是否合法由基类的约定决定。
- **返回**：返回类型标注为 `MemoryItem`。它直接返回 `self.add(...)` 的返回值，因此实际返回的就是基类写入后构造出的记忆条目对象——通常包含事件内容、时间戳、元数据、重要度以及由基类分配的 id 等信息。本方法自身不构造、不包装、不转换这个返回值，属于原样透传。
- **内部流程**：整个方法体只有一条语句：`return self.add(event, timestamp=timestamp, metadata=metadata, importance=importance)`。执行顺序上，先通过 `self` 查找 `add` 方法——由于本类没有定义 `add`，会沿 MRO 找到父类 `BaseMemory.add`；然后以位置参数传入 `event`，以关键字参数传入 `timestamp`、`metadata`、`importance`，参数名与基类 `add` 的形参名一一对应；最后把基类返回的 `MemoryItem` 直接作为本方法的返回值交还给调用方。方法内部没有条件分支、没有循环、没有异常捕获，也没有调用本文件内的任何其他函数。
- **异常/边界**：本方法自身不抛出任何异常，也不做任何输入校验。边界情况全部依赖基类：`event` 为空字符串时不会被本方法拦截；`timestamp` 为 `None` 或格式非法的字符串时，本方法照常转发，是否报错取决于 `BaseMemory.add`；`metadata` 为 `None` 或非映射对象时同样原样转发；`importance` 超出常见范围（如小于 0 或大于 1）时也不做处理。若基类 `add` 抛出异常（例如类型错误、存储失败、超时），该异常会不加捕获地向上传播给调用方。唯一与关键字相关的边界是：因为使用了 `*` 分隔符，`timestamp`、`metadata`、`importance` 都不能按位置传入，否则会抛 `TypeError`。
- **同文件关系**：它被本文件中的类 `EpisodicMemory` 所包含（是其实例方法），并调用父类 `BaseMemory.add`（父类不在本文件内）。本文件内没有任何函数调用它；文件内也没有定义它调用到的其他本文件函数。

| `EpisodicMemory` | 继承 `BaseMemory` 的情景记忆实现类，用类属性 `memory_type = MemoryType.EPISODIC` 标识自身类型，并提供记录事件的方法。 |
