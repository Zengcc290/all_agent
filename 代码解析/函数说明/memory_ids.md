# memory/ids.py

## 一、这个文件是干什么的

这个文件是记忆系统里专门负责「生成稳定标识符」的叶子模块（leaf module）。所谓叶子模块，是指它按设计只依赖 Python 标准库（`hashlib`、`json`、`re`、`collections.abc`、`typing`）和项目里的 `constants`，不导入记忆系统内部的任何其它模块。文档字符串里明确说明了这样做的两个理由：一是避免 `manager -> types.semantic -> rag.knowledge -> manager` 这样的循环导入；二是保证不管事实数据是从 `memory.types.semantic` 这条路写进去的，还是从 `memory.rag.knowledge` 那条路写进去的，最终算出来的 id 都是同一套方案、同一个值。

文件的核心职责可以拆成三层：第一层是文本归一化（`_clean_text`、`normalize_entity_name`），把五花八门的实体名、谓词名、时间字符串压成可比较的规范形式；第二层是基于归一化结果做哈希，生成实体 id（`entity_id_for`）、关系 id（`relation_id_for`）、观测 id（`observation_id_for`）、槽位 key（`predicate_key_for`）；第三层是历史兼容（`legacy_fact_id_for`），为统一 id 方案之前写入数据库的老数据保留可读形式的 id，让 `add_fact` 能够就地更新旧行而不是插入重复行。

在实际运行中，四层记忆系统每当抽取出一条知识（实体、三元组、带时间与参与者的 n 元观测）时，都会调用这里的函数来算出该条知识的唯一键；数据库以此键作为主键或去重依据，于是「同一条知识重复写入」变成幂等操作，而「同一三元组在不同时间点成立」则能作为两条独立记录共存。文件末尾的 `__all__` 列出了 6 个对外公开的符号，即除私有辅助函数 `_clean_text` 之外的全部函数。

## 二、函数与类逐条详解

### `_clean_text(value: Any, *, max_length: int = ENTITY_CLEAN_MAX_LENGTH) -> str` （第 21 行）

- **作用**：这是整个模块最底层的文本清洗工具，负责把任意类型的输入安全地变成一个「紧凑、无多余空白、长度受控」的字符串。它存在的意义在于：调用方传进来的可能是 `None`、数字、列表，也可能是带换行和连续空格的脏文本，如果不先统一清洗，后面的哈希就会因为一个多余空格而产生完全不同的 id，导致同一实体在库里出现多份。它被本模块中几乎所有其它函数间接或直接调用，是 id 稳定性的第一道防线。默认长度上限取自 `constants.ENTITY_CLEAN_MAX_LENGTH`，使得清洗规则在整个项目里集中配置、不散落。
- **参数**：
  - `value: Any`：待清洗的原始值。类型不做限制，因为函数内部会先做 `isinstance` 判断，任何非字符串类型都会被当作「空」来处理。
  - `max_length: int`：关键字限定参数（`*` 之后，只能以 `max_length=...` 形式传入），默认值 `ENTITY_CLEAN_MAX_LENGTH`。表示截断后允许保留的最大字符数；调用方会传入不同的值，例如观测 id 里对时间字段传 80、对 `source_id` 传 300。
- **返回**：始终返回 `str`。如果 `value` 不是字符串，返回空字符串 `""`；否则返回把内部所有空白折叠为单个空格、截断到 `max_length` 个字符、再去掉首尾空白后的结果。返回值理论上可能仍是空字符串（例如输入是 `"   "` 或 `"None"` 之外的纯空白字符串）。
- **内部流程**：第一步用 `isinstance(value, str)` 判断类型，不是字符串就直接 `return ""` 提前退出，避免对非文本对象调用字符串方法而报错。第二步执行 `value.split()`，不带参数的 `split()` 会按任意空白（空格、制表符、换行）切分并自动丢弃空片段。第三步用 `" ".join(...)` 把这些片段用单个空格重新拼接，实现「空白归一化」。第四步用切片 `[:max_length]` 截断长度。第五步调用 `.strip()` 去掉截断后可能残留在首尾的空白（例如截断点刚好落在空格上）。最终把这条链式表达式的结果返回。
- **异常/边界**：不会抛异常。对 `None`、数字、列表、字典等非字符串输入统一返回 `""`，不尝试做 `str()` 转换。`max_length` 若传 0 会得到空字符串，传负数会得到除尾部若干字符外的结果（Python 切片语义），但模块内部调用点都使用正整数。超长文本静默截断，不报错也不提示。
- **同文件关系**：被 `normalize_entity_name`（限制实体名长度）和 `observation_id_for`（清洗 `event_at`、`valid_from`、`valid_to`、`source_id`）调用。它自身不调用本文件里的任何其它函数。

### `normalize_entity_name(value: str) -> str` （第 27 行）

- **作用**：把一个「给人看的实体名/谓词名」转换成「给程序比较用的稳定 key」，同时不破坏原始展示标签——因为调用方在调用它之前或之后仍然保留原文用于显示，它只负责产出比较键。它解决了同一实体因大小写、空格、标点差异而被判为不同实体的问题：例如 `"OpenAI"`、`"openai"`、`"Open AI!"`、`"open-ai"` 都应该落到同一个 key 上。函数还特意保留了中日韩统一表意文字区段（`\u4e00-\u9fff`）的字符，使得中文实体名（如 `"余额"`、`"张三"`）不会被当成标点清掉。整个记忆系统的实体去重、关系去重都以它为基础。
- **参数**：
  - `value: str`：原始实体名或谓词名。类型标注为 `str`，但实际实现通过 `_clean_text` 做了容错，传非字符串不会崩溃，只会得到空 key。
- **返回**：返回 `str`。正常情况返回一个只含「单词字符」（`\w`，即字母、数字、下划线，且带 `re.UNICODE` 时包含各语言字母数字）和中文汉字的字符串，且已经 `casefold()` 小写化。如果输入为空、纯空白、纯标点或非字符串，则返回空字符串 `""`。
- **内部流程**：第一步调用 `_clean_text(value, max_length=ENTITY_NAME_MAX_LENGTH)`，把输入折叠空白并按实体名上限截断。第二步对结果调用 `.casefold()` 做比 `lower()` 更彻底的大小写折叠（能正确处理德语 `ß` 等特殊字符）。第三步用 `re.sub(r"[^\w\u4e00-\u9fff]+", "", value, flags=re.UNICODE)` 把所有「既不是单词字符也不是汉字」的连续片段整体删除（替换为空串），从而去掉标点、空格、emoji 等噪声。第四步返回替换后的字符串。
- **异常/边界**：不会抛异常。对非字符串、`None`、空串返回 `""`。注意它可能返回空字符串，因此任何直接把它当 id 素材使用的地方都必须自行判断空值——这正是 `entity_id_for` 里 `if not key: raise ValueError(...)` 的由来。截断发生在清洗之前，所以极端长的实体名可能被截掉尾部内容后再参与哈希。
- **同文件关系**：调用 `_clean_text`。被 `entity_id_for`、`relation_id_for`、`observation_id_for`、`predicate_key_for` 调用，是这四个 id 生成函数的公共前置步骤。

### `entity_id_for(name: str) -> str` （第 34 行）

- **作用**：为「一个实体」生成全局稳定、与书写形式无关的唯一 id。记忆系统在写入实体节点时必须有一个不受大小写和标点影响的键，否则同一实体每被抽取一次就会新建一个节点，图谱会被同名实体撑爆。它把归一化后的名字做 SHA-256 摘要并取前 20 个十六进制字符，再加 `entity:` 前缀，得到一个定长、可读性尚可、几乎不会碰撞的字符串。相对关系 id 它取的长度更短（20 位），因为实体数量通常最多，节省存储与索引开销；同时它强制要求名字里至少有一个可检索字符，避免把「空实体」写进库。
- **参数**：
  - `name: str`：实体名，可以是任意语言、任意大小写、含标点与空白的文本，例如 `"OpenAI"`、`" 张三 "`、`"GPT-4o"`。
- **返回**：返回形如 `entity:<20 位十六进制>` 的字符串，例如 `entity:3f2a...`（共 20 个 hex 字符）。当归一化后 key 为空时不会返回任何值，而是抛出 `ValueError`。
- **内部流程**：第一步调用 `normalize_entity_name(name)` 得到比较 key。第二步用 `if not key:` 判断 key 是否为空，为空则抛出 `ValueError("entity name must contain at least one searchable character")`，这是本模块唯一的显式异常。第三步把 key 用 UTF-8 编码后交给 `hashlib.sha256(...).hexdigest()` 求摘要。第四步用 `[:20]` 截取前 20 个字符。第五步拼接前缀 `"entity:"` 返回。
- **异常/边界**：当名字为空串、纯空白、纯标点、或类型不是字符串（归一化返回空）时抛出 `ValueError`，错误信息为英文提示「实体名必须至少包含一个可检索字符」。对超长名字不报错，由归一化阶段按 `ENTITY_NAME_MAX_LENGTH` 截断。哈希理论上存在碰撞可能，但 20 位十六进制（80 位）在实际数据量下可忽略。
- **同文件关系**：调用 `normalize_entity_name`（后者又调用 `_clean_text`）。本文件中没有其它函数调用它；它通过 `__all__` 对外导出，供记忆系统的实体写入路径使用。

### `relation_id_for(subject: str, predicate: str, object: str) -> str` （第 42 行）

- **作用**：为一条「主语—谓词—宾语」三元组关系生成稳定 id。它是早期/基础版本的 id 方案，只考虑三元组本身、不考虑时间与来源，因此语义是「这条关系是否存在」而不是「这条关系在某个时刻的某次观测」。当记忆系统需要把抽取出的三元组作为图中的边写入、并按边去重时就会用到它。它与 `observation_id_for` 形成对照：后者把时间、来源、附加参与者全部纳入身份，前者刻意不纳入。
- **参数**：
  - `subject: str`：主语实体名，任意文本形式，内部会被归一化。
  - `predicate: str`：谓词/关系名，例如 `"任职于"`、`"works_at"`，同样会被归一化。
  - `object: str`：宾语实体名或字面值，同样会被归一化。
- **返回**：返回形如 `relation:<24 位十六进制>` 的字符串。注意它不做空值校验，即使三个参数全为空也会正常返回一个基于 `"||"` 计算的摘要值。
- **内部流程**：第一步分别对 `subject`、`predicate`、`object` 调用 `normalize_entity_name`，得到三个归一化片段。第二步用 `"|".join((...))` 以竖线为分隔符把三段拼成一个 key，这里使用元组并按固定顺序（主语、谓词、宾语）拼接，保证顺序敏感、方向敏感——`(A, 关系, B)` 与 `(B, 关系, A)` 会得到不同 id。第三步用 `hashlib.sha256(key.encode("utf-8")).hexdigest()[:24]` 取 24 位摘要。第四步拼接 `"relation:"` 前缀返回。
- **异常/边界**：无特殊处理。任何输入（包括 `None`、空串、纯标点）都不会抛异常，只会得到归一化后的空片段并参与拼接。因为分隔符 `"|"` 在归一化阶段已被删除，所以不存在「某个字段里含竖线导致拼接歧义」的问题。哈希碰撞概率同样可忽略。
- **同文件关系**：调用 `normalize_entity_name`。本文件中没有其它函数调用它；通过 `__all__` 对外导出，供三元组关系写入路径使用。

### `observation_id_for(subject: str, predicate: str, object: str, *, roles: Sequence[Mapping[str, Any]] | None = None, event_at: str = "", valid_from: str = "", valid_to: str = "", source_id: str = "") -> str` （第 53 行）

- **作用**：为一条「n 元、带时间限定」的观测记录生成稳定 id，是本文件里最复杂、最贴近新版记忆语义的函数。与 `relation_id_for` 的关键区别是：它的身份里额外包含了时间（`event_at`、`valid_from`、`valid_to`）、来源（`source_id`）以及所有附加参与者（`roles`）。这样设计带来两个重要性质：其一，同一个三元组在不同时间点成立时会被视为两条不同观测，可以共存（例如「某人的余额」在 3 月和 6 月各有一条）；其二，把同一段来源文本重复处理一遍时，因为所有身份要素完全一致，算出的 id 也一致，写入操作天然幂等，不会产生重复行。文档字符串里对这两点有明确说明。凡是记忆系统写入带时间与来源的事实（尤其是 RAG 抽取出来的观测）都会经过它。
- **参数**：
  - `subject: str`：主语实体名，必填，内部归一化。
  - `predicate: str`：谓词/关系名，必填，内部归一化。
  - `object: str`：宾语实体名或字面值，必填，内部归一化。
  - `roles: Sequence[Mapping[str, Any]] | None`：关键字限定参数，默认 `None`。表示这次观测里除主三元组之外的其它参与者角色列表，每个元素应是一个映射（通常是 dict），里面通过 `role` 和 `value` 两个键描述「角色名」和「角色取值」。为 `None` 时按空列表处理。
  - `event_at: str`：关键字限定参数，默认 `""`。事件发生时间（字符串形式，例如 ISO 时间戳），清洗后最长保留 80 个字符。
  - `valid_from: str`：关键字限定参数，默认 `""`。该事实的生效起始时间，清洗后最长 80 个字符。
  - `valid_to: str`：关键字限定参数，默认 `""`。该事实的失效时间，清洗后最长 80 个字符。
  - `source_id: str`：关键字限定参数，默认 `""`。来源标识（例如文档块 id、消息 id），清洗后最长保留 300 个字符，因为来源标识往往比实体名长得多。
- **返回**：返回形如 `observation:<24 位十六进制>` 的字符串。只要三个必填字符串能被归一化（哪怕全为空）就会正常返回，函数本身没有显式的空值校验和异常分支。
- **内部流程**：第一步用列表推导式遍历 `roles or []`，对每一个 role 映射取出 `role.get("role")` 与 `role.get("value")`，各自用 `str(... or "")` 兜底避免 `None` 报错，再用 `normalize_entity_name` 归一化，构造出只含 `role`、`value` 两个键的新字典。第二步在这个推导式里附带 `if` 过滤条件：只有当 `role` 和 `value` 去掉首尾空白后都非空时才保留该项，从而剔除残缺的角色条目。第三步用 `sorted(..., key=lambda role: (role["role"], role["value"]))` 对结果按「角色名、角色取值」的元组排序，这一步至关重要——它让角色的传入顺序不影响最终 id，即「同一组角色以不同顺序传入」仍然得到同一个观测 id。第四步构造 `payload` 字典，包含归一化后的 `subject`、`predicate`、`object`，排序后的 `roles` 列表，以及用 `_clean_text` 分别按 80、80、80、300 长度上限清洗的 `event_at`、`valid_from`、`valid_to`、`source_id`。第五步用 `json.dumps(payload, ensure_ascii=False, sort_keys=True, separators=(",", ":"))` 把 payload 序列化成紧凑且键序固定的 JSON 字符串：`ensure_ascii=False` 保留中文原文（哈希的是 UTF-8 字节，可读性更好且不引入转义差异），`sort_keys=True` 保证字典键顺序稳定，`separators=(",", ":")` 去掉默认空格使编码唯一。第六步对编码后的字符串求 SHA-256 并取前 24 位十六进制。第七步拼接 `"observation:"` 前缀返回。
- **异常/边界**：对 `roles` 为 `None`、空列表、元素不是映射、缺少 `role`/`value` 键等情况都能容错（缺键时 `role.get(...)` 返回 `None`，被 `or ""` 兜底成空串，再被过滤条件剔除）。对非字符串的 `event_at` 等时间参数，`_clean_text` 会返回空串而不是报错。唯一可能的异常来自 `roles` 元素不是 `Mapping`（例如传入字符串列表）时调用 `.get` 会抛 `AttributeError`，函数本身不做类型校验；另外若 `roles` 传入的是不可迭代对象也会抛 `TypeError`。时间字段只做清洗不做格式解析，因此非法时间字符串会被原样（截断后）纳入哈希，不会报错也不会被忽略。所有字段为空时函数仍返回一个合法 id。
- **同文件关系**：调用 `normalize_entity_name`（间接调用 `_clean_text`）和 `_clean_text`。本文件中没有其它函数调用它；通过 `__all__` 对外导出，供带时间与来源的观测写入路径使用。

### `predicate_key_for(subject: str, predicate: str) -> str` （第 99 行）

- **作用**：生成标识「某一个（主语, 谓词）槽位」的稳定 key，注意它刻意忽略了宾语。文档字符串举了 `余额`、`当前版本` 这样的例子：这类单值槽位在任一时刻只应有一个当前值，当同一槽位写入更新的值时，需要能把前一个值「退休」掉（标记失效或被替换）而不是并列保留两条互相矛盾的事实。实现方式就是让同一 `(主语, 谓词)` 的先后两次写入共享同一个槽位 key，于是上层可以用这个 key 找到旧记录并更新。它和 `relation_id_for` 的差别正是「含不含宾语」这一点。相对 `relation_id_for` 它直接返回裸的摘要字符串（没有 `relation:` 之类的前缀），因为它表示的是一个内部槽位而不是一个可寻址的实体。
- **参数**：
  - `subject: str`：主语实体名，会被归一化。
  - `predicate: str`：谓词名，会被归一化。
- **返回**：返回一个 24 位十六进制摘要字符串，**不带任何前缀**。对空输入不做校验，同样返回一个合法摘要。
- **内部流程**：第一步分别对 `subject` 和 `predicate` 调用 `normalize_entity_name`。第二步用 `"|".join((...))` 按「主语在前、谓词在后」的固定顺序拼成 key。第三步用 `hashlib.sha256(key.encode("utf-8")).hexdigest()[:24]` 取前 24 位十六进制并返回。整个过程没有缓存、没有分支。
- **异常/边界**：无特殊处理。任何输入（含 `None`、空串、纯标点）都不会抛异常；归一化产生的空片段会照常参与拼接。不校验主语或谓词是否为空，因此调用方若要拒绝空槽位需自行判断。哈希碰撞概率可忽略。
- **同文件关系**：调用 `normalize_entity_name`。本文件中没有其它函数调用它；通过 `__all__` 对外导出，供单值槽位（如余额、当前版本）的更新/退休逻辑使用。

### `legacy_fact_id_for(subject: str, predicate: str, object: str) -> str` （第 112 行）

- **作用**：为「统一 id 方案之前写入数据库的老事实行」生成它们当年使用的那种可读 id，用于历史数据兼容。文档字符串说明：早期事实使用 `fact:<主语>|<谓词>|<宾语>` 这种人类可读的形式，后来才统一成哈希方案；`add_fact` 在找不到规范（新）id 时会回退到调用本函数，从而定位到旧行并就地更新，避免同一事实在库里出现新旧两份重复记录。因此这个函数只在兼容路径上被用到，新写入的数据不会以它为主键，但它的存在保证了老数据库升级后不会数据翻倍。
- **参数**：
  - `subject: str`：主语原文。
  - `predicate: str`：谓词原文。
  - `object: str`：宾语原文。
- **返回**：返回形如 `fact:主语|谓词|宾语` 的字符串，三段之间用竖线分隔，前面带 `fact:` 前缀。返回值中的三段是原始文本 `.strip()` 后的结果。
- **内部流程**：第一步分别对三个参数调用 `.strip()` 去掉首尾空白（注意：只去首尾，不做大小写折叠、不删内部标点、不折叠内部空白，因为必须与历史写入时完全一致才能命中旧行）。第二步用 f-string 按 `f"fact:{subject.strip()}|{predicate.strip()}|{object.strip()}"` 拼接并直接返回。没有哈希、没有长度截断、没有分支判断。
- **异常/边界**：无特殊处理，但有一个隐含前提：参数必须是字符串，因为直接调用了 `.strip()`；若传入 `None` 或其它类型会抛 `AttributeError`，函数不做类型兜底（这与其它函数依赖 `_clean_text` 的容错风格不同，是刻意保持与历史写法一致的结果）。输入中含竖线时无法与拼接结果区分，属于历史格式的固有限制。不做长度截断，超长文本会原样进入 id。
- **同文件关系**：不调用本文件里的任何其它函数（这也是它与其它 id 函数的显著区别：它不经过 `normalize_entity_name`，以保持与历史 id 逐字节一致）。本文件中没有其它函数调用它；通过 `__all__` 对外导出，由 `add_fact` 在规范 id 缺失时回退使用。

## 三、一句话总览表

| 函数/类 | 一句话作用 |
| --- | --- |
| `_clean_text` | 把任意类型的输入安全地转成折叠空白、截断到指定长度并去掉首尾空白的字符串，非字符串返回空串。 |
| `normalize_entity_name` | 把实体名/谓词名清洗、折叠大小写并删除除单词字符与汉字外的所有字符，得到稳定的比较 key。 |
| `entity_id_for` | 用归一化实体名的 SHA-256 前 20 位生成 `entity:` 前缀的实体唯一 id，名字不可检索时抛 `ValueError`。 |
| `relation_id_for` | 用主语、谓词、宾语三段归一化后拼接的 SHA-256 前 24 位生成 `relation:` 前缀的三元组关系 id。 |
| `observation_id_for` | 把三元组、附加角色、事件时间、生效区间和来源一起序列化成规范 JSON 后哈希，生成 `observation:` 前缀的 n 元带时间观测 id。 |
| `predicate_key_for` | 用主语与谓词（忽略宾语）的 SHA-256 前 24 位生成无前缀槽位 key，供单值槽位退休旧值。 |
| `legacy_fact_id_for` | 生成历史遗留的可读 id `fact:<主语>\|<谓词>\|<宾语>`，供 `add_fact` 回退匹配老数据行以免重复插入。 |
